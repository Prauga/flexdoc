# FlexDoc package release 3.5.0

FlexDoc **3.5.0** publishes the Node disagreement loop. Package semver stays independent of product-milestone labels.

## Behavior change

**This is not a backwards-compatible minor.** The 3.x package line is not strict SemVer. A dependency written as `@prauga/flexdoc-backend` `^3.4.0` can resolve to 3.5.0 on a fresh install, and a service that previously passed validation with only an undocumented-route warning then fails the default check without a configuration change. That failure is the point of the release.

When runtime discovery is complete, an implemented route that OpenAPI does not document is an error. `flexdoc validate` exits 1 and names the method and path. Partial discovery keeps that finding a warning.

## Licensing

`@prauga/flexdoc-client`, `@prauga/flexdoc-backend`, and `@prauga/flexdoc-cli` are published under Apache-2.0 in this release. The 3.4.0 client and backend packages, and CLI 0.7.0, recorded `AGPL-3.0-or-later` in their package metadata. Apache-2.0 applies to the artifacts published from this release. It does not replace tarballs already on the registry.

- `@prauga/flexdoc-client` — **3.5.0**
- `@prauga/flexdoc-backend` — **3.5.0**

`@prauga/flexdoc-core` and the native adapter lines are unchanged. This wave does not change their behavior. Examples and the install tables are pinned to these versions.

## What the loop does

`runtimeIntelligence.acknowledgedUndocumented` marks a chosen route as acknowledged info. The route remains in the runtime record, `summary.runtime` still counts it, and the acknowledgement does not fail validation.

Opening the finding shows the missing contract beside the registered method and path. The API Client can send that route. The URL uses the snapshot `serverOrigin` when the runtime reported one, and is a same-origin path otherwise. The request prefers the API host only when host execution is available and the server has not set `preferHostExecution` to false.

The page does not invent a handler, a schema, parameters, or auth for a route the contract does not declare.

## Host execution

The `@prauga/flexdoc-backend` **3.5.0** host-execution contract is unchanged from 3.4.0. [`docs/host-execution-operations.md`](../host-execution-operations.md) still describes that contract.

## Release sequencing

This wave used the version contract's in-flight window. Examples and install documentation stayed pinned to the previously published artifacts while source versions sat in `pending`. After the registry artifacts existed, the follow-up repin updated examples, generated lock metadata, and the published baselines, then cleared `pending`. That window is closed for 3.5.0.
